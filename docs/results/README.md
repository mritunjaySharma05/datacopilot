## Notes: answerability classifier (2026-11-18)

**Test split (180 questions).** The first main model (2026-11-17; logistic regression,
C = 0.1, all 24 features) reached 90.6% accuracy; unanswerable precision 90.1%, recall 91.1%.

**Human held-out set (30 questions).** The same model drops to 66.7% (10 errors).
Logistic regression trained the same way without `n_words` scores 83.3% (5 errors), while
its test-split accuracy barely changes (90.0%).

- The main model's errors follow question length: 7 short answerable questions
  ("avg review score?", "kharif vs rabi total area") were refused, and 3 long, chatty
  unanswerable questions were accepted (P(answerable) 0.51 to 0.79). In our authored sets,
  unanswerable questions were written shorter (about 7 vs 10 words), so `n_words` learned
  a writing-style shortcut that the test split shares but real-style questions do not.
- Without `n_words`, the remaining errors are (a) three short Hinglish answerable
  questions about derived metrics ("kohli ne total kitne sixes mare", "bumrah ki overall
  economy", "verstappen ke ... podiums"): `schema_overlap` is 0 because sixes, economy
  and podiums are computed, not column names, and lowercase names are not counted as
  entities; (b) two `missing_column` questions (female customers, farmers' earnings)
  whose words partly match real columns.
- **Caveat:** 30 questions is small (one question = 3.3 points), and the held-out
  questions were AI-drafted and human-edited, some paraphrasing training questions. The
  direction of the `n_words` result is clear; its size is uncertain.

## Decision: `n_words` dropped from the deployed model (2026-11-18)

Based on the fair logreg ablation above, `n_words` is left out of the deployed model
(`answerability.EXCLUDED_FEATURES`). The model was retrained with the unchanged grouped-CV
procedure over all three families on the remaining 23 features; CV chose **XGBoost**
(learning_rate 0.05, max_depth 5, 300 trees; CV macro F1 0.886 ± 0.033). Test split:
87.2% accuracy (unanswerable precision 86.8%, recall 87.8%), below the 90.6% of the old
model on test. `with_n_words` is now the ablation in `answerability.md`.

**The held-out set is no longer fully untouched.** It was used once to make a modelling
decision: dropping `n_words`. No other choice (model family, hyperparameters, threshold,
features) was made from it. After the decision, the retrained model was scored on it once
for reporting (86.7%, 4 errors, in `heldout.md`); that score was not used to choose
anything and must not be used for later choices either. Treat held-out numbers as
optimistic from now on; a fresh untouched set is needed for a clean final estimate.

## Known limitation for Module 6: feature vocabulary gap

Not fixed on purpose: adding features because of held-out misclassifications would fit
the model to the held-out set. Questions about derived metrics get `schema_overlap = 0`
because the metric words are not column names ("sixes", "economy", "podiums": all
computed from `runs_off_bat`, runs/balls, `position <= 3`), and lowercase player names
("kohli", "bumrah", "verstappen") are not counted as entities, although they match data
values ("V Kohli"). Short Hinglish questions about such metrics are refused
(human-002, human-004 still wrong with the deployed model). Module 6 options: a
domain-metric vocabulary per dataset, or matching against values case-insensitively in
the entity features, validated on new questions, not the held-out set.

## Notes: SQL pipeline, validated vs baseline (2026-11-18, step 3)

qwen2.5-coder:7b, temperature 0, no few-shot examples. Test split = 90 answerable
questions (60 English, 30 Hinglish); human held-out = its 15 answerable questions.

**Metrics.** Strict is the primary metric: the predicted result has the same rows and
values as the gold answer (row order counts if the gold SQL has an outer `ORDER BY`).
Relaxed is secondary. **The relaxed rules below were defined after seeing the first step 3
results** (decision 2026-11-18), to stop counting two kinds of correct answers as wrong;
the numbers under them are therefore not a pre-registered measurement:

1. every gold column appears in the prediction (extra columns allowed, numbers rounded to
   the gold column's precision), or exactly the gold's non-aggregate key columns appear
   (the count / aggregate is left out, e.g. "Which venue hosted the most matches?"
   answered with the venue only; a wrong count next to the right key is not accepted);
2. row order counts only for ranking / top-N questions (gold has `ORDER BY` and
   `LIMIT > 1`), not for presentation-only `ORDER BY`.

Columns that are stored values (e.g. `points` read from the standings table) count as
keys, so "who scored the most points" answered without the points is still wrong. BIRD
keeps its standard execution accuracy (same set of rows), unchanged.

| Set | Validated strict | Baseline strict | Validated relaxed | Baseline relaxed |
|---|---|---|---|---|
| Test (90) | 33.3% | 33.3% | 47.8% | 47.8% |
| Held-out answerable (15) | 20.0% | 20.0% | 46.7% | 46.7% |

The stored runs were rescored with the new relaxed rules (`eval_questions.py --rescore`,
same SQL re-executed, no new LLM calls): strict unchanged on every question; relaxed
gained 10 test questions (ipl-021, ipl-028, ipl-034, ipl-045, f1-018, f1-020, f1-028,
crop-011, ipl-034-hi, f1-020-hi) and 3 held-out (human-003, human-005, human-014) and
lost none. Under the old relaxed rule the figures were 36.7% (test) and 26.7% (held-out).

- **The two modes do not differ on our sets.** The validator rejected 5 test queries
  (baseline: 6 execution errors instead) and changed the final SQL of 4 of 90 questions,
  but none of those retries produced a correct answer, so per-question correctness is
  identical: 0 discordant pairs, McNemar p = 1.0 on both sets and both metrics. Almost
  all failures (55 of 60 validated failures on test) are valid SQL that returns the
  wrong answer, which a schema check cannot catch. On BIRD (smoke test, 10 questions)
  validation gained one question; step 5 measures this at scale.
- **Hinglish is lower** (26.7% vs 36.7% English strict); F1 is the weakest dataset (13.0%
  strict), e.g. counting a cancelled race (f1-019), summing cumulative standings across
  rounds instead of taking the latest (f1-011), or counting top-3 championship positions
  after each round as podiums instead of race results (f1-025).
